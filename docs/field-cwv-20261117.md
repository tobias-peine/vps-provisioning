# Feld-Core-Web-Vitals — 17.11.2026

## Ziel

Prüfen, ob für `https://kisium.de/` echte Feldwerte aus dem Chrome UX Report
(CrUX) vorliegen — nicht Lighthouse-Laborwerte.

## Vorgehen

- PageSpeed Insights v5: `runPagespeed`, `strategy=mobile`, `category=performance`,
  URL `https://kisium.de/`.
- CrUX API: `queryRecord` für URL und Origin, `formFactor` `PHONE` und `DESKTOP`.
- API-Key lokal aus einer 600er-Datei gelesen; nicht im Repo, nicht in Logs.

## Ergebnis

| Abfrage | HTTP | Feldmetriken |
|---|---|---|
| PSI `loadingExperience` | 200 | 0 |
| PSI `originLoadingExperience` | 200 | 0 |
| CrUX URL / PHONE | 404 | `chrome ux report data not found` |
| CrUX Origin / PHONE | 404 | `chrome ux report data not found` |
| CrUX URL / DESKTOP | 404 | `chrome ux report data not found` |
| CrUX Origin / DESKTOP | 404 | `chrome ux report data not found` |

## Interpretation

- Für die Domain liegen **keine ausreichenden realen Nutzungsdaten** vor.
- Feld-CWV sind damit **nicht verfügbar**, nicht „gut“ und nicht „schlecht“.
- Die vorhandenen Lighthouse-Werte (TBT-Median 119 ms, LCP ~2,1 s) bleiben
  ausdrücklich **Laborwerte** und ersetzen keine Feldmessung.

## Nächster Schritt

- Mehr Traffic abwarten und später erneut abfragen, oder
- Search Console CWV-Report prüfen (bei fehlenden CrUX-Daten wahrscheinlich
  ebenfalls ohne Daten), oder
- RUM ergänzen — das ist eine Datenschutzentscheidung, kein technischer Default.
